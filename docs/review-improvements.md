# 代码评审改进实施记录

依据 2026-11-14 的多 agent 评审实施；当前记录以工作树为准。

## 已实施

- 账户：密码工作使用有界阻塞池，注册/登录按socket peer及账户限流；改密先校验，再在账户行锁和事务内原子更新，令牌版本撤销旧JWT。桌面授权码绑定签发时版本，无法在改密后换出新会话。可选认证同样检查版本与账户状态。
- 部署：JWT密钥必填且至少32字节，拒绝占位值；数据库密码必填，数据库不发布宿主端口。部署前设置新的随机密钥，旧JWT需重新登录；不自动修改本机私有配置。
- 订阅：账户级事务锁，过期状态归一化，数据库部分唯一索引保障单一有效订阅，一次性试用领取记录；钱包初始化原子化。
- 学习统计：按单调时钟的实际间隔计时，用户级去重，累计亚秒余量，跨UTC日期分配；保留在途刷盘批次，事务与UUID账本保证失败重试/提交确认丢失时不重复累计；停机结束请求后执行最终刷盘。
- 前端：错误输入框保留红色边框并增加独立键盘焦点环；迟到的录音授权停止自身stream，不污染新录音；普通请求和流式响应拒绝跨会话数据；设备AI编辑器跨tab保留，说明两组保存按钮的作用域；小程序后台恢复保留复习进度，身份切换仍清空；路由标题与导航焦点管理。
- 工程：库与生产入口统一；禁止丢弃must_use结果；修复OAuth/流式数据库测试的漏await；QA使用正常workspace下的独立profile可执行文件，不停止现有开发服务。
- 发布：后端使用vendor/amigo源码快照；更新时执行 `python scripts/sync-amigo-protocol.py` 并审查diff，CI通过 `--check` 校验文件摘要。网站和Docker构建不再从移动分支获取相邻仓库。固件仍以amigo仓库为源。
- CI：隔离PostgreSQL、假上游、真实WASM页面的UI/响应式回归，以及安全/一致性故障测试；固件增加两板型ESP-IDF目标编译门禁。Gitea产物步骤采用官方发布说明提到的适配上传action：[Gitea 1.22说明](https://blog.gitea.com/release-of-1.22.0/)。
- 固件工具：旧build/setup/package入口也从所属workspace的cargo metadata取产物目录。

## 保证边界

统计批次仍在进程内保留；可恢复数据库故障和优雅停机，进程被强杀或主机掉电时尚未刷盘的增量可能丢失。若产品需要跨崩溃不丢，应另加持久化事件日志。真实麦克风权限/BFCache、微信真机、读屏、声学和生产负载仍需专用环境验收；CI目标构建配置不等于已经在远端执行成功。
