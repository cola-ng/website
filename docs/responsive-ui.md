# 响应式布局复检

在保留桌面布局及统一配色、字号的基础上，优化以下场景：

- 950px 及以下使用紧凑导航；平板首页改用完整宽度的主区，任务和洞察并排显示，避免统计数字被挤断。
- 聊天页独立使用可见视口，历史消息自行滚动。手机的对话列表、改名及操作入口放入工具栏，输入区不再被固定最小高度推到屏幕之外。
- 通过原生 `visualViewport` 监听可见高度变化，兼顾虚拟键盘和安全区域；缩放时保留浏览器原生放大与平移。
- 手机词典标签横向排列，并同步实际键盘方向。跨断点切换时保留当前词条分区。
- 窄屏翻译设置默认折叠，保持翻译按钮易于找到；展开状态与翻译选项分别保存，改变布局不会重置选项。
- 600px 及以下将后台表格行呈现为带字段标签的卡片，保留原生表格及列标题语义，操作按钮可直接触达。较大屏幕保持表格和可聚焦的滚动容器。
- 长昵称、邮箱、头像区域和长表单适应窄屏；表单关闭按钮滚动时保持可见，常用触控操作至少有 44px 高度。

`tests/responsive.cjs` 使用实际 WASM 与隔离接口数据，覆盖 320×568、360×640、390×844、768×1024、820×1180、1024×768、1440×900、844×390 和 390×430。检查页面溢出、聊天输入区、表格操作、长弹窗、标签键盘导航、断点切换后的状态和草稿保留。

键盘检查模拟“布局视口仍为 844px、可见视口缩小至 430px”的浏览器 API；它不等同于在实体 iOS/Android 设备上操作真实输入法。

运行时指定已构建的本地预览：

```powershell
$env:QA_WEB='http://127.0.0.1:5173'
node tests/responsive.cjs
```

可通过 `PLAYWRIGHT_MODULE` 使用开发机已有的 Playwright。报告及截图保存在该 workspace 的 `target_directory/qa-responsive`；测试不读取用户浏览器凭据，也不调用真实 AI 服务。
