# Colang 多 Agent 代码评审与后续改进报告

日期：2026-11-14，Asia/Shanghai。

后续实施：本报告保留评审时的发现；修复内容、迁移规则、验证结果及剩余限制见[改进实施记录](../review-improvements.md)。

## 核心结论

项目已有较好的协议边界、取消与背压机制、OAuth 约束及本地替身测试基础。下一阶段最值得投入的是账户安全、异步生命周期和数据一致性，以及让现有测试真正形成发布门禁。当前证据不足以给出生产容量、界面视觉质量或硬件体验评分。

优先处理：默认部署配置可导致身份边界失效；改密码链路在数据库故障时跳过旧密码检查；迟到的麦克风授权在离页后仍启动录音；学习时长写入失败会丢数据；并发订阅会生成重复有效记录。默认单元测试绿灯不能覆盖这些问题，其中两项显式数据库测试本身已经失效。

## 优先级改进清单

以下按风险与先后依赖排序。编号指向后文专项报告，其中包含更细的行号、影响、修复方案与验收步骤。

| P1 · SEC-06/07 | 使用仓库默认 Compose 时，公开 JWT 占位密钥可用于伪造令牌；固定口令数据库发布到所有宿主接口，外部可达时绕过应用鉴权。均为部署条件风险。 | 密钥改为必填 secret，启动拒绝占位；去除 DB ports 或仅绑定 loopback。缺失/弱配置不能启动，外部不能直连 DB。 |
| P1 · SEC-01 | 改密查询错误被 `.unwrap_or(false)` 当成无密码，若后续数据库写恢复便跳过旧密码验证。 | 查询错误失败关闭；事务内确认与替换。故障注入后接口失败、原密码不变。 |

## 界面设计、效率与可维护性的后续优化

这些属于待测改进，不计为已实测的界面缺陷：

1. **先保住用户操作成果**：统一设备页面两组保存动作、显示未保存区域；复习恢复、录音取消和会话切换都采用一致的状态归属规则。表单输入不因查看日志、轮询或网络迟到响应消失。
2. **补导航可访问性**：路由更新 document title，按导航方式管理主标题/主内容焦点；用键盘与读屏验证新页可感知，错误与异步状态可获知。沿用已有焦点与响应式测试基础。
3. **稳定渲染身份**：Amigo 列表/日志用稳定 ID 作 key，避免整个JSON变化导致卡片重建；在轮询期间验证焦点保持与输入不丢。没有测量前不预设帧率收益。
4. **数据库做聚合**：学习汇总把全量 mastery Vec 改为 AVG/条件聚合，核对 NULL 和空集语义，以相同数据集比较查询计划、传输量、p95。
5. **按业务责任演进代码**：会话管理、媒体流、配置和持久化分开；由库暴露同一个 app 构造，主程序只负责启动。先为高风险交错与业务不变量补测试，再拆分大型模块。
6. **建立成本与故障预算**：本地可回放假上游模拟慢AI、慢客户端、断库、取消，记录首token/首音频、p50/p95/p99、每设备内存、池等待、队列长度、取消后存活任务。后续再据实决定缓存、批处理或并行度；不凭静态代码承诺吞吐提升百分比。
7. **执行真实体验矩阵**：320/375/768/1280宽度、200%字号、软键盘、横屏、键盘/读屏、高对比模式；设备侧补弱网重连、Wi-Fi配置、触摸、摄像头指示、打断与回声的真机验收。现有host测试不替代这些验收。
