# 安全、鉴权与付费边界评审

日期：2026-11-14。范围：website 当前工作树（含未提交修改），静态追踪路由、鉴权、改密、订阅、设备配对与 AI 提供方调用；未启动攻击、未访问外部服务、未读取或记录实际密钥。以下“已确认”指代码路径已确认，并不代表已经在生产环境复现攻击。

## SEC-01 [P1] 改密查询失败时跳过旧密码验证

- 证据：`D:/Works/colang/website/crates/server/src/routing/account.rs:356` 查询是否存在密码，`:366` 将任何查询错误转换为 `false`，`:369` 仅在 `has_password` 为 true 时验证旧密码，`:389` 起仍会保存新密码。
- 触发：持有有效用户 JWT 的请求抵达改密接口；首次密码状态查询因暂时数据库/连接问题失败，而后续写操作成功。
- 影响：一个本应要求旧密码的账户被当成“尚未设置密码”，允许未知旧密码的会话重置密码。前置 require_auth 的查询成功不能保证随后查询也成功。
- 修复：查询错误返回 503；仅明确查到不存在密码时允许设置首个密码。对密码记录/用户行加锁，在事务内完成状态确认与替换。
- 验证：注入第一次查询失败而后续连接恢复，接口必须失败且原密码保持有效；设置首个密码与正常修改分别测试。
- 置信度：高，故障条件下的授权失败开放路径；未做数据库故障注入。

## SEC-02 [P1] 修改密码后已有 JWT 继续有效

- 证据：`D:/Works/colang/website/crates/server/src/auth.rs:15` 的 claims 仅有 sub/exp/iat；`D:/Works/colang/website/crates/server/src/hoops/auth.rs:52` 只检查账户 disabled_at/locked_at；`D:/Works/colang/website/crates/server/src/routing/account.rs:389` 改密仅替换密码；`D:/Works/colang/website/crates/server/src/config.rs:49` JWT 默认存活七天。
- 触发：用户发现凭据/会话泄漏后修改密码，攻击者仍持有尚未过期的 JWT。
- 影响：攻击者可继续访问账户、AI 配置操作及设备管理直至令牌过期；改密无法完成常见的账户恢复动作。
- 修复：为用户增加 token_version 或 credentials_changed_at，将其与 claims 校验；改密时事务内递增版本并给当前会话换发令牌。设备长连接撤销策略应另做明确设计。
- 验证：登录两次，第一次改密，第二次令牌随后访问 /api/me 必须 401；正常新令牌可用。
- 置信度：高，现有请求认证链没有改密失效条件。

## SEC-03 [P1] 公开注册/登录没有应用限流，Argon2 同步占用运行时

- 证据：`D:/Works/colang/website/crates/server/src/routing/account.rs:21` 附近注册/登录路由直接绑定 handler；`:143` 在检查重复邮箱前做密码哈希；`D:/Works/colang/website/crates/server/src/auth.rs:21`、`:47` 同步执行 Argon2；`D:/Works/colang/website/crates/server/src/hoops.rs:74` 的 limit_rate 仅返回 Ok，主路由也未接入限流。
- 触发：匿名并发提交注册（包括重复邮箱）或对真实账户并发提交登录。
- 影响：CPU/内存昂贵的密码工作挤占 Tokio worker；同时缺少口令猜测的应用级约束。实际容量取决于服务器和入口代理策略。
- 修复：注册/登录按 IP 和账户标识分别限制速率；哈希/验证移至 spawn_blocking，并用有界 semaphore 控制总并发，过载返回 429/503。不要用永久账户锁定为攻击者提供锁号能力。
- 验证：以不存在及存在的邮箱分别做有界负载测试，确认响应 429、工作队列有上限，健康接口 p95 不因密码工作明显失控。
- 置信度：应用层缺失与同步调用高；外部代理是否另有防护未验证。不宣称已成功造成生产拒绝服务。

## SEC-04 [P2] 密码替换缺少事务，失败可留下无密码账户

- 证据：`D:/Works/colang/website/crates/server/src/routing/account.rs:392` 的 with_conn 块先 DELETE 后 INSERT，没有 horme::transaction。with_conn 提供连接并不等于数据库事务。
- 触发：DELETE 成功后 INSERT 因连接中断、约束或存储故障失败。
- 影响：接口返回失败，但旧密码已删除；原生账户失去密码登录能力。并发改密也不能保证一个清晰的原子结果。
- 修复：用用户行锁与事务，优先对唯一 user_id 密码记录做 UPSERT/UPDATE；与 SEC-01 一起实现，避免另加互相冲突的写路径。
- 验证：在删除后插入前注入失败，确认事务回滚且原密码仍有效；并发改密只能得到一致的最终密码记录。
- 置信度：高，未做实际数据库中断。

## SEC-05 [P2] 取消后可无限重复领取试用

- 证据：`D:/Works/colang/website/crates/server/src/routing/payment.rs:294` 仅排除当前 active/trial 订阅；`:335` 只判断请求试用且 trial_days > 0；`:414` 取消将状态改成 cancelled。没有查询历史试用领取记录。
- 触发：订阅试用 → 取消 → 再次订阅同一试用计划，循环调用。
- 影响：试用历史和产品资格失真，可持续创建新的 trial；当前 `services/mod.rs:132` 附近平台 AI 资格要求真实 paid 订单，因此不能据此声称可免费盗用平台 AI。
- 修复：引入用户/产品族唯一的试用领取记录，在同一事务中原子领取；明确取消与试用权益的业务语义。
- 验证：首次领取成功，取消后再次请求不再获得新试用；并发请求最多一次成功。
- 置信度：高；经济影响取决于未来/实际试用权益。

## SEC-06 [P1] Compose 默认令牌签名密钥为公开固定占位值

- 证据：`D:/Works/colang/website/compose.yml:12` 硬编码公开占位 JWT_SECRET；`D:/Works/colang/website/crates/server/src/config.rs:45` 只检查变量存在，未拒绝占位或过短值；`D:/Works/colang/website/crates/server/src/auth.rs:81` 用该共享密钥验证 HS256 JWT。
- 触发：直接采用仓库 Compose 配置部署且未手动改密钥。
- 影响：知道占位值者可以签发任意 sub 的 JWT；require_auth 只要求该用户存在且未锁定，因此会失去身份边界。这里没有认定实际生产正在使用该值。
- 修复：Compose 改为必填环境变量 `${JWT_SECRET:?JWT_SECRET is required}` 或 secret 文件；应用启动拒绝已知占位值与不足强度的值。若此默认配置曾经外部部署，应轮换密钥并撤销旧令牌。
- 验证：缺少密钥/占位密钥必须无法启动；随机真实密钥正常启动；用旧占位值签出的令牌必须 401。
- 置信度：高，配置条件下可利用，未访问实际部署。

## SEC-07 [P1] Compose 将固定口令数据库发布到宿主所有接口

- 证据：`D:/Works/colang/website/compose.yml:42` 数据库采用固定示例口令；`:46` 将 7654 映射至数据库 5432，未限定 127.0.0.1。应用本身通过 Docker 内部 db:5432 连接，不依赖此公开端口。
- 触发：采用该 Compose 且宿主防火墙允许外部访问 7654。已有持久卷可能保留先前密码，因此实际口令需部署侧确认。
- 影响：按默认首次初始化的实例可被外部以已知凭据直接连接数据库，绕过全部应用鉴权，读取或修改账户、AI 密钥及设备绑定记录。
- 修复：删除数据库 ports，仅保留容器内网络；若确需本机管理绑定 127.0.0.1；密码采用必填 secret 并为应用配置最小权限用户。
- 验证：检查 Compose 渲染结果，数据库没有 0.0.0.0/[::] 发布端口；从外部网络无法连接；内部应用数据库连接正常。
- 置信度：配置风险高，宿主网络暴露情况未验证。此次未执行任何 Docker 构建。
